# Season English (GFT)

App web tĩnh gồm 3 file (`index.html` khung trang, `style.css`, `core.js`; không cần cài đặt hay build) hiện thực PRD "Season English": test đầu vào CEFR, bài học do AI sinh theo trình độ, AI coach "Season" luyện tập, theo dõi và nhắc học. Giao diện theo bộ thiết kế "Season English" (chữ Be Vietnam Pro, bảng màu nắng/ô liu/nâu) nhưng bố cục kiểu công cụ làm việc cho người đi làm: sidebar trái trên desktop (thanh trên + nav dưới trên điện thoại), thẻ trắng viền mỏng bo 14, nút chữ nhật bo 10, màu vàng chỉ dùng cho hành động chính và tiến độ, gần như không emoji trang trí; mascot "Season" là logo mặt trời không mặt (sprite trong mini game vẫn có mặt). Bộ da "Season sticker" cũ (thư mục `design/`) vẫn còn ở `style.sticker.css`: muốn dùng lại chỉ cần đổi link trong `index.html`.

## Cài đặt và chạy dự án (bàn giao cho Back-end)

### Yêu cầu

| Thành phần | Phiên bản |
|---|---|
| Node.js | **≥ 18 LTS** (khuyến nghị 20 LTS) – chỉ để chạy dev server; app không có bước build |
| npm | ≥ 9 (đi kèm Node) |
| Trình duyệt | Chrome / Edge mới (Web Speech API, MediaRecorder, IndexedDB, Web Audio) |

Front-end là **vanilla JS, không build, không dependency runtime**: `index.html` + `style.css` + `core.js` (+ `logic-v2/useAppLogicV2.ts` là lớp logic headless cho UI V2). `npm install` không cài gì (dependencies rỗng) nhưng vẫn chạy để tạo `package-lock.json` theo quy trình chung.

### Các bước

```bash
# 1. Lấy mã nguồn và vào thư mục dự án
git clone <repo-url> season-english
cd season-english

# 2. Cài đặt (không có dependency; lệnh vẫn chạy được để chuẩn hoá quy trình)
npm install

# 3. Tạo file môi trường từ mẫu rồi sửa giá trị (PORT, API_BASE_URL…)
copy .env.example .env        # Windows
# cp .env.example .env        # macOS / Linux

# 4. Chạy dev server (server.js, zero-dependency) và mở trình duyệt
npm run dev
# → http://localhost:8080/            dữ liệu thật của trình duyệt (localStorage `aec:v1`)
# → http://localhost:8080/?sandbox=1  kho dữ liệu riêng để thử nghiệm, không đụng dữ liệu thật
```

Lệnh khác: `npm start` (như `dev`), `npm run check` (kiểm tra cú pháp `core.js`). Thay thế không cần Node: mở `index.html` trực tiếp bằng Chrome/Edge, hoặc `powershell -ExecutionPolicy Bypass -File serve.ps1 -Port 8080`.

### Biến môi trường

Xem `.env.example`. Dev server đọc `.env`, phục vụ app và xuất các giá trị **công khai** ra `/config.js` (`window.__SEASON_CONFIG__`: `API_BASE_URL`, `APP_ENV`, `ORG_NAME`). Hiện tại front-end chưa gọi back-end: mọi dữ liệu nằm trong localStorage và AI được gọi thẳng từ trình duyệt bằng key nhập ở Cài đặt. Khi có API, front-end sẽ đọc `API_BASE_URL` từ `/config.js`; key AI chuyển về server (`ANTHROPIC_API_KEY`… trong `.env`, không bao giờ lộ ra trình duyệt).

### Hợp đồng dữ liệu cho Back-end

`docs/api-contract.json` mô tả **mọi thực thể** front-end đang dùng (User, Settings, Week, LessonSet/Lesson, Progress, Activity, PracticeResult, CoachSession, Submission, Test/TestDraft/TestForm, LevelForm, LevelRequest, Reminder, Appeal, DeleteRequest, TrashItem, PinReport, TopicReport, Survey, MicroLesson, GameSet, GameResult, Duel) kèm mẫu dữ liệu thật trích từ dữ liệu demo, danh sách enum, các endpoint REST đề xuất và 12 tác vụ AI cần proxy. Mock data hiện nằm ở `core.js` (`seedDemo`, `DEMO_LESSONS`, `demoLevelForm`, `TEST_FORMS`, `GAME_POOL`) và cũng được gom trong file hợp đồng (mục `mockDataSources`). Kiểu dữ liệu TypeScript tương ứng: `logic-v2/useAppLogicV2.ts` (interface `AppState`, `User`, `Lesson`, `TestRecord`…), tóm tắt API logic ở `logic-v2/API-V2.md`.

### Cấu trúc thư mục

```
index.html              khung trang (chỉ #app, #toast, #saved, #modal)
style.css               giao diện (theme theo mùa, layout chuyên nghiệp)
core.js                 toàn bộ logic + render (app hiện hành)
logic-v2/               useAppLogicV2.ts (logic headless cho UI V2) + API-V2.md
server.js, package.json dev server Node zero-dependency (npm run dev)
serve.ps1               dev server PowerShell (không cần Node)
.env.example, .gitignore
docs/                   api-contract.json, sơ đồ luồng, ảnh chụp màn hình
design/                 logo GFT (dùng trên chứng nhận), đề thi PDF gốc, mockup
```

## Chạy app (cách cũ, không cần Node)

- Cách 1: mở `index.html` trực tiếp bằng Chrome/Edge (đủ cho dùng thật và demo). Ba file `index.html`, `style.css`, `core.js` phải nằm cùng thư mục; khi copy app đi nơi khác, copy cả ba (và `design/gft-logo.png` cho chứng nhận).
- Cách 2 (preview trong Claude Code / nhiều máy trong LAN): chạy `serve.ps1` rồi mở `http://localhost:8080`.

```bash
powershell -ExecutionPolicy Bypass -File serve.ps1 -Port 8080
```

Phông chữ Baloo 2 và Nunito tải từ Google Fonts; không có mạng thì app dùng phông hệ thống, mọi chức năng khác vẫn chạy.

## Lần đầu sử dụng

1. Mở app → **Tạo người vận hành** (hoặc **Nạp dữ liệu mẫu** để xem thử toàn bộ; PIN của học viên mẫu là `1234`).
   - Màn vào app hỏi **"Bạn là…"**: Người học đăng nhập bằng họ tên + mã PIN cá nhân (tự đăng ký bằng "Tôi là người mới", hoặc tài khoản do vận hành tạo thì đặt PIN ở lần vào đầu) và không thấy danh sách người khác. Vận hành và quản lý chọn tài khoản của vai trò mình (có PIN vai trò nếu đặt trong Cài đặt) và thấy toàn bộ.
   - Mỗi tài khoản có **avatar ngỗng** riêng (8 màu lông × 8 phụ kiện × 5 màu nền): bấm vào avatar ở thanh trên hoặc nút **Đổi avatar** trong trang **Tiến độ & hồ sơ** (trang này cũng có nút Sửa hồ sơ); vận hành đổi hộ trong Cài đặt → Người dùng.
   - **Đăng nhập học viên phân biệt chữ HOA/thường và dấu** ở họ tên (chỉ bỏ qua khoảng trắng thừa); gõ sai kiểu chữ sẽ có thông báo riêng. Cảnh báo Caps Lock chỉ hiện khi phím đang bật.
   - Quên PIN: vận hành vào Cài đặt → Người dùng → **Đặt lại PIN**. PIN lưu dạng thường trong localStorage, chỉ để tránh vào nhầm trên máy dùng chung, không phải bảo mật thật.
2. Vào vai trò Người vận hành → **Cài đặt**:
   - **Nhà cung cấp AI** (bấm *Kiểm tra kết nối* sau khi nhập):
     - *Claude*: key tại platform.claude.com, cần nạp credit. Chất lượng tốt nhất cho pilot thật.
     - *Google Gemini*: key miễn phí tại aistudio.google.com/apikey, model mặc định `gemini-3.8-flash`. Tài khoản Google cần bật xác minh 2 bước; dự án có thể bị Google đánh dấu "Restricted".
     - *OpenAI-compatible* (miễn phí để chạy thử): chọn preset **Groq** (đăng ký bằng Google/GitHub, không cần thẻ, key tại console.groq.com/keys), **OpenRouter** (model đuôi `:free`), **Cerebras**, hoặc **Ollama** chạy trên máy (không cần key; đặt `OLLAMA_ORIGINS=*` để trình duyệt gọi được). Nên dùng model 70B trở lên để JSON ổn định.
   - Gói miễn phí nào cũng giới hạn request/phút; dữ liệu bài làm gửi tới nhà cung cấp, chỉ nên dùng để chạy thử.
   - Lịch pilot: ngày bắt đầu (Thứ Hai tuần 1), số tuần, phút học tối thiểu/ngày.
   - **Webhook Base.vn**: Base Message → nhóm chat → menu "…" → *Tích hợp incoming webhook* → dán URL. Payload mặc định `{"base_content":"{message}"}`.
   - PIN cho vai trò vận hành/quản lý (tuỳ chọn).
3. **Chủ đề tuần**: nhập chủ đề, mô tả, mục tiêu cho từng tuần, hoặc bấm **✨ Gợi ý** (từng tuần hoặc "các tuần còn trống") để AI đề xuất dựa trên nghề, mục đích và mức của nhóm học viên, tránh lặp chủ đề đã dùng. Gợi ý hiện thành **bảng 3 phương án ngay dưới ô chủ đề**, mỗi phương án có trọng tâm cho từng mức CEFR đang có học viên; bấm **Xác nhận** ở một dòng để điền và lưu tuần đó tại chỗ (vẫn sửa tay rồi *Lưu khung chủ đề* được).
4. Thêm người học ở màn chọn người dùng. Mỗi người làm 2 bước: **Hồ sơ cá nhân** (công việc, mục đích dùng tiếng Anh, phong cách học yêu thích, ngôn ngữ giải thích, lịch học, tự đánh giá) rồi **test đầu vào** theo đề "Workplace English CEFR Placement Test": Nghe 15 câu (3 đoạn, giọng đọc trình duyệt, tối đa 2 lần/đoạn), Đọc 15 câu (3 bài), Viết 150–200 từ (rubric 5 tiêu chí), Nói 3 task qua micro hoặc gõ (rubric 4 tiêu chí, không chấm phát âm). Mỗi kỹ năng 25 điểm; CEFR theo bảng quy đổi của đề (tổng: A1 0–24, A2 25–39, B1 40–59, B2 60–79, C1 80–100).
   - **Tính giờ**: mỗi phần có đồng hồ riêng (mặc định Nghe 15 / Đọc 20 / Viết 20 / Nói 15 phút, chỉnh trong Cài đặt). Cảnh báo khi còn 5 phút và 1 phút; hết giờ tự chuyển phần, hết phần Nói tự nộp. Không quay lại phần đã nộp. Thời gian vẫn chạy nếu thoát ra giữa chừng.
   - **Onboarding**: trang chủ người mới hiện 3 bước (Hồ sơ → Test → Duyệt mức) kèm lý do "Vì sao cần?". Form hồ sơ có nút *Quay lại* và *Lưu tạm* (lưu phần đang điền, chưa tính là xong bước 1). Bài test **không có lưu tạm hay tạm dừng**: màn giới thiệu nêu rõ trong nhóm "Lưu ý" và hỏi xác nhận khi bấm Bắt đầu; câu trả lời vẫn được tự lưu để không mất khi lỡ tải lại trang, nhưng đồng hồ chạy liên tục.
   - **Đếm ngược 5 giây**: mọi hành động tự động của bài test (hết giờ chuyển phần, hết giờ nộp bài, đủ số cảnh báo) hiện hộp đếm ngược 5 giây rồi mới thực hiện. Mọi thao tác không hoàn tác được (xoá tài khoản, duyệt xoá, xoá bài / bộ bài, sinh lại bộ bài, xoá chat, đặt lại PIN, xoá toàn bộ dữ liệu, nạp dữ liệu mẫu, nộp phần thi, nộp bài) sau khi bấm xác nhận cũng đếm ngược 5 giây, có nút **Dừng lại**.
   - **Thử thiết bị**: màn giới thiệu bài test có nút *Thử tai nghe* (phát câu mẫu) và *Thử micro* (ghi 3 giây rồi phát lại), làm trước khi đồng hồ chạy.
   - **Xem trước phần thưởng**: trang `#/reward/preview` (nút trong Tiến độ & hồ sơ của học viên và trang Tiến độ của quản lý) giả lập màn hình khi đạt đủ huy hiệu; không ghi gì vào dữ liệu. Màn thật tự hiện một lần khi học viên đạt đủ.
   - **Chống gian lận**: cấm mở tab, cửa sổ, pop-up khác; chặn chuột phải và sao chép/dán. Mỗi lần rời màn hình bị cảnh báo kèm âm thanh, tối đa 3 lần (chỉnh trong Cài đặt); vi phạm lần thứ 4 bài tự nộp. Trình duyệt không cho trang web chặn hẳn việc mở tab, nên app phát hiện và xử lý thay vì ngăn. Phần Nói nộp bằng file ghi âm (ghi tại trang hoặc tải lên). Nhật ký cảnh báo và thời gian từng phần hiện cho vận hành khi xem bài.
   - Viết/Nói do AI chấm theo rubric ngay khi nộp; không có AI thì điểm tạm theo độ dài và vận hành chấm tay trong hộp "Xem bài làm" (nhập 0–5 từng tiêu chí, lưu). Bài cuối kỳ hiện dùng cùng đề; muốn đề khác, thêm `TEST_FORMS.B` cùng cấu trúc trong `core.js`. Hồ sơ được đưa vào prompt để AI chọn ví dụ sát việc và cách học hợp với từng người; sửa lại bất cứ lúc nào ở trang Tiến độ.
5. **Duyệt mức**: xem điểm từng phần + gợi ý CEFR của AI + hồ sơ, chọn mức và duyệt. Vận hành và quản lý đều có nút **Xoá** học viên (xoá kèm toàn bộ dữ liệu học, có xác nhận).
6. **Bài học siêu ngắn theo ngày (tối ưu token)**: vận hành bấm *Sinh* ở ma trận tuần × mức → một prompt ngắn duy nhất (không kèm prompt nền) trả về **5 bài cho T2–T6**, mỗi ngày một mẫu câu khác nhau trong chủ đề tuần, mỗi bài gồm lý thuyết (công thức + dùng khi nào + 2–3 ví dụ gắn nghề), 3 từ vựng có trong ví dụ, 1 bài tập **chỉ một đáp án đúng** (điền từ luôn có gợi ý nghĩa trong ngoặc; trắc nghiệm một đáp án, lựa chọn sai rõ ràng). Vận hành xem/sửa/duyệt cả bộ. Học viên thấy **"Bài hôm nay"** theo thứ trong tuần (bỏ dở thì bài còn dở được ưu tiên, cuối tuần ôn bài chưa xong), và danh sách T2–T6 của tuần. `theory` bắt buộc là nội dung dạy (1 mẫu câu + giải thích + 2 ví dụ gắn nghề), không phải mô tả bài. `practice` là đối tượng `{type: write|fill|mcq, prompt, options, answer}` áp dụng đúng mẫu câu đó và ≥2 từ vocab; ô làm bài đổi theo dạng (ô viết + micro / ô điền từ / trắc nghiệm). Với fill và mcq app chấm ngay theo đáp án rồi AI giải thích; với write AI chấm bằng prompt ngắn thứ hai trả `score/10 · ok · feedback · fix`, luôn kèm lý thuyết, từ vựng và đáp án mẫu của chính bài đó. Không có AI vẫn chấm được fill/mcq theo đáp án. Trong lý thuyết có nút **Nghe mẫu câu** chỉ đọc phần tiếng Anh (công thức và câu ví dụ, bỏ giải thích tiếng Việt), kèm từng dòng có loa riêng. Từ vựng có **ảnh minh hoạ** từ kho ảnh miễn phí, không qua AI, chọn trong Cài đặt → Ảnh minh hoạ: **Pexels** hoặc **Pixabay** (đúng nghĩa nhất, cần key miễn phí, giấy phép dùng tự do không bắt buộc ghi nguồn), **Openverse** (Creative Commons, không cần key), **Wikimedia** (không cần key), hoặc tắt. Nguồn không có ảnh thì rơi về Wikimedia; ảnh cache trong trình duyệt, có nút xoá cache và nút thử. Nút Hoàn thành chỉ mở sau khi nộp (hoặc khi không có AI). Bài do học viên tự tạo hiện ở Đọc mẫu → tab *Bài siêu ngắn* để kiểm tra/xoá. Cả hai prompt sửa được ở Cài đặt → Prompt (giữ nguyên tên biến và key JSON).
7. Hằng tuần: học viên học 3–4 bài, luyện với Season ≥2 lượt, nộp bài thứ Sáu (AI chấm rubric đúng ý · từ vựng · ngữ pháp, tối đa 3 gợi ý). Vận hành vào **Đọc mẫu** để kiểm tra bài nộp và phản hồi của coach, chỉnh **Prompt** nếu AI lệch mức.
   - **Cấu trúc chuẩn của bài (từ bản S3)**: mỗi bài có 3 thành phần (Từ vựng kèm IPA, Ngữ pháp, Phát âm) và 4 kỹ năng (Nghe: audio đọc bằng giọng trình duyệt + 1 câu hỏi; Đọc: đoạn ngắn + 1 câu hỏi; Viết: bài tập mẫu câu; Nói: nói câu mẫu, nộp bằng file ghi âm). Đầu bài hiện rõ **Mục tiêu bài học** và **Hướng dẫn làm bài**. Bộ bài sinh trước bản này chỉ có phần Viết; bấm *Sinh lại* để có đủ cấu trúc.
   - **Giữ đúng mức CEFR**: khi sinh bài, app tự gắn vào prompt bảng giới hạn của từng mức (`LEVEL_SCOPE` trong `core.js`: cấu trúc được dùng, cấu trúc cấm, số từ tối đa mỗi câu), áp dụng cả khi prompt đã bị sửa tay. Sau khi AI trả về, app soát các lỗi vượt mức hay gặp (hoàn thành tiếp diễn, hiện tại hoàn thành ở A1–A2, điều kiện loại 2/3, câu nói mẫu quá dài); bài lỗi được sinh lại một lần, còn sót thì hiện cảnh báo cho vận hành khi duyệt. Phép soát chỉ bắt lỗi phổ biến, không thay việc đọc duyệt.
   - **Từ luyện phát âm đúng âm mục tiêu**: AI phải trả IPA cho từng từ; app chỉ giữ từ có IPA chứa âm mục tiêu và tự bù cho đủ 3 từ từ danh sách đã kiểm chứng trong app (`SOUND_WORDS`, 43 âm × 5 từ thông dụng). Âm nằm ngoài danh sách mà AI không đưa đủ 3 từ đúng thì bài bị gắn cảnh báo.
   - **Gói miễn phí**: lời gọi sinh bài không gửi kèm schema (đã có mẫu JSON trong prompt) và đặt mức suy luận thấp cho model `gpt-oss` để vừa hạn mức token/phút; nếu kết quả vẫn bị cắt, app tự sinh thành hai nửa tuần và chờ 1 phút khi dính giới hạn.
   - **Dữ liệu mẫu theo cấu trúc chuẩn**: *Nạp dữ liệu mẫu* tạo sẵn 4 bộ bài tuần 1 (A1, A2, B1, B2), mỗi bộ 5 bài T2–T6 đủ từ vựng + 3 cụm từ, ngữ pháp, phát âm, 4 kỹ năng và bản dịch (soạn tay trong `DEMO_LESSONS`, không cần AI). Dữ liệu mẫu nạp từ bản cũ (bài định dạng cũ) được tự chuyển sang bộ mới khi mở app.
   - **Thứ tự trong bài**: Mục tiêu → Hướng dẫn → **Từ vựng** → **Ngữ pháp** → Phát âm → Nghe → Đọc → Viết → Nói.
   - **Cụm từ cho từ vựng**: mỗi từ có 3 cụm từ / collocation thông dụng theo chủ đề, bấm để nghe. App chỉ nhận cụm thật sự chứa từ đó; từ nào thiếu thì gọi AI bổ sung riêng. Bộ bài cũ: mở bộ bài → nút *Bổ sung cụm từ bằng AI* (bộ bài trở về Bản nháp để đọc lại), hoặc bấm ✏️ Sửa ở bài đó và điền ô cụm từ trong form (3 cụm cách nhau bằng dấu `;`).

Trượt ở bước nào cũng phải đủ **3 điều kiện thi lại** (`retakePlan`): đợi 14 ngày, giữ đủ 4 tín hiệu, và luyện lại đúng chỗ yếu kể từ lúc trượt: yếu Viết → 2 bài thực hành tuần ≥80; yếu Nghe/Đọc/Nói → ≥4 phần đó trong bài học với ≥80% đúng ngay lần đầu; trượt ở thử thách Season → ≥10 lượt chat mới trung bình ≥4/5. Học viên thấy checklist ✅/◻️ trên thẻ; vận hành thấy ở ô "Đang trong luồng lên mức".
   - **Đề thi lên mức** (Vận hành → Duyệt mức → *đề thi lên mức*, `#/op/levelforms`): *Sinh đề bằng AI* theo từng mức đích (prompt riêng, kèm giới hạn ngữ pháp của mức; tự sinh lại một lần nếu đoạn nghe/đọc quá ngắn, vẫn ngắn thì gắn nhãn ⚠️), *Xem* (đáp án tô xanh), *Duyệt* (mỗi mức một đề đang dùng), *Xoá* (không xoá được đề đã có bài thi). Dữ liệu mẫu có sẵn đề B2 và C1.

Chế độ tự động theo ngày hoặc cố định một theme ở Cài đặt → *Giao diện theo mùa / lễ* (S.settings.theme). Màu trạng thái (đúng/ô liu, cảnh báo/kem, lỗi/nâu) và sprite mini game không đổi theo theme.
   - **Quyền của Người vận hành với tài khoản**: chỉ quản lý **học viên** (tạo, đổi tên, đổi avatar, đặt lại PIN, yêu cầu xoá) và đổi tên/avatar của chính mình. Không đổi vai trò của bất kỳ ai (cột Vai trò chỉ hiện chữ), không tạo/đổi tên/yêu cầu xoá tài khoản Vận hành khác hay Quản lý. Quản lý làm được tất cả, trừ tự hạ vai trò của tài khoản đang đăng nhập.
   - **Show PIN**: Cài đặt → Người dùng có nút *Show PIN* cho từng học viên; Vận hành và Quản lý đều xem được. PIN lưu dạng thường, chỉ để tránh vào nhầm tài khoản.
   - **Quên PIN vận hành**: khi vai trò Vận hành có PIN, màn chọn tài khoản vận hành có nút *Báo Quản lý cấp lại PIN* → chọn tên, ghi chú cách liên hệ → tạo yêu cầu `S.pinReports` (mỗi người một yêu cầu đang mở, gửi lại chỉ tăng đếm). Quản lý thấy thẻ **Mã PIN** ở Tiến độ nhóm và Vận hành: yêu cầu đang chờ kèm PIN vận hành hiện tại và nút *Đã báo lại*; mục xổ *Tất cả mã PIN trong hệ thống* liệt kê PIN vai trò Vận hành, Quản lý và PIN của từng học viên (chỉ Quản lý). Enter trong mọi hộp thoại có ô nhập (hộp PIN, đăng ký, quên PIN…) tương đương bấm nút chính.
   - **Quản lý xem màn hình vận hành**: mục **Vận hành** của Quản lý mở được Duyệt mức, Chủ đề tuần, Bài học, Đọc mẫu, Prompt ở chế độ chỉ xem (mọi nút thao tác bị chặn).
   - **Hiệu suất vận hành**: với từng người vận hành: số bộ bài / số bài soạn theo tuần, tỉ lệ đã duyệt, số bài đủ cấu trúc chuẩn, chất lượng qua kết quả học viên (điểm trung bình, tỉ lệ đúng lần đầu, tỉ lệ hết lượt vẫn sai), thời gian chờ duyệt mức, số bài đã đọc mẫu. Người soạn được ghi nhận từ bản này (người bấm Sinh / Duyệt).
9. Tuần cuối: học viên làm **bài cuối kỳ** (cùng rubric bộ B) và **khảo sát**.

## Dữ liệu và API key

- **Cô lập dữ liệu theo học viên**: tiến độ (`progress`), kết quả từng phần (`practiceResults["userId_lessonId~phần"]`), bản nháp bài test (`testDrafts["userId:loại"]`), chat, bài nộp đều gắn `userId`. Mọi lần đổi người dùng đi qua `setSessionUser()`, hàm này xoá toàn bộ trạng thái đang giữ trong bộ nhớ của người trước (bài đang làm dở, bài test đang chạy, đếm ngược, ghi âm).
- **Chế độ thử (sandbox)**: mở `http://localhost:8080/?sandbox=1` để dùng một kho dữ liệu riêng (`aec:v1:sandbox`). Mọi thứ làm ở đó không đụng tới dữ liệu thật của trình duyệt; dùng khi muốn nạp dữ liệu mẫu hoặc thử tính năng.

- Toàn bộ dữ liệu nằm trong `localStorage` của trình duyệt (khoá `aec:v1`). Dùng *Xuất JSON* để sao lưu / chuyển máy, *Nhập JSON* để khôi phục.
- Vì không có server, mỗi trình duyệt cần API key để gọi AI (coach, chấm bài). Cách đơn giản cho pilot: vận hành xuất JSON (có kèm cài đặt) và học viên nhập vào máy mình. Key dùng chung trong nhóm nội bộ nên đặt hạn mức chi tiêu và xoay key sau pilot. Bước sau MVP: backend nhỏ giữ key.
- Model mặc định `claude-opus-5-5`; có thể chọn `claude-sonnet-5-5` hoặc `claude-haiku-4-5` để giảm chi phí.
- Webhook gửi bằng `fetch` chế độ `no-cors` nên app không đọc được phản hồi của Base; kiểm tra tin đến nhóm chat lần đầu bằng nút *Gửi tin thử*.
